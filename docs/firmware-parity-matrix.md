# Firmware parity matrix: C++ (`osww-server`) vs Rust (`winderoo-esp32`)

This document compares **all observable features** between:

- C++ firmware: `src/platformio/osww-server/src/main.cpp` (+ `src/platformio/osww-server/src/utils/*`)
- Rust firmware: `src/rust/winderoo-esp32` (and its runtime dependencies in `src/rust/osww-embassy` + `src/rust/osww-firmware`)

Generated by direct code inspection on **2026-01-02**.

Legend (per cell):

- **Yes** = implemented + used
- **Partial** = implemented but reduced scope / different UX / not wired / behavior differs
- **No** = absent

## Build variants / compile-time surface

| Feature | C++ (PlatformIO `osww-server`) | Rust (`winderoo-esp32`) | Parity notes |
|---|---|---|---|
| OLED support | **Yes** (`OLED_ENABLED`): Adafruit SSD1306 UI + sleep/scheduling | **Yes** (`features=["oled"]`): SSD1306 UI + sleep/scheduling | Rust UI now closely mirrors the Arduino layout (see OLED section). |
| OLED invert/rotate | **Yes** (`OLED_INVERT_SCREEN`, `OLED_ROTATE_SCREEN_180`) | **Yes** (`OLED_INVERT_SCREEN`, `OLED_ROTATE_SCREEN_180`) | Same knobs, different driver stack. |
| Home Assistant | **Yes** (`HOME_ASSISTANT_ENABLED`): ArduinoHA + many entities | **Yes** (`features=["home-assistant"]`): patched `embassy-ha` + full entity set | Rust now matches the ArduinoHA surface (selects + text sensors + raised entity cap). |
| HA broker config | **Yes**: hardcoded constants; **halts** if placeholders | **Partial**: build-time `WINDEROO_HA_BROKER`; **auto-disables** if placeholder | C++ fails-fast; Rust runs without HA. |
| mDNS | **Yes** (ESPmDNS) | **Yes** (default `mdns` feature via `edge-mdns`) | Same service name + port advertised. |
| Motor PWM control | **Yes** (optional `PWM_MOTOR_CONTROL` + MX1508) | **Partial** (optional `pwm-motor` feature: MX1508-style two-PWM driver) | Default Rust build still assumes L298N-style direction pins. |
| LED “PWM ramp” patterns | **Yes** (LEDC ramp-based pulse/blinks) | **Yes** (LEDC + PWM ramp-based pulse/blinks) | Rust now uses LEDC PWM and matches the Arduino-style ramp patterns. |

## HTTP server + routes (API surface)

| Surface | C++ | Rust | Parity notes |
|---|---|---|---|
| HTTP server | **Yes**: `ESPAsyncWebServer` on `:80` | **Yes**: `picoserve` on `:80` | Rust runs **two** HTTP servers: one on STA and one on AP. |
| CORS headers | **Yes**: global default headers | **Yes**: baked into response writer | Both allow `*`, `GET,POST,OPTIONS`. |
| OPTIONS / preflight | **Yes**: “catch-all” handler returns OK for OPTIONS | **Yes**: explicit `.options(cors_preflight)` per route | Equivalent outcome. |
| `/api/status` (GET) | **Yes** | **Yes** | Response schema matches very closely (see next table). |
| `/api/update` (POST) | **Yes** | **Yes** | Rust validates strictly + parses multiple input types (string/number/bool). |
| `/api/power` (POST) | **Yes** | **Yes** | Rust persists `winderEnabled`; C++ does not. |
| `/api/timer` (POST) | **Yes** (query param only) | **Yes** (query param **or** JSON body) | Rust is more tolerant. |
| `/api/reset` (GET) | **Yes** | **Yes** | Both clear Wi‑Fi creds and reboot; settings are preserved. |
| `/api/wifi` (POST) | **No** | **Yes** | Rust-native provisioning path (set SSID/password via JSON). |
| Static frontend hosting | **Yes**: served from LittleFS (whatever files are flashed) | **Yes**: embedded static assets (gzipped JS/CSS/HTML + i18n) | Rust frontend is compiled into firmware image; C++ can swap frontend via FS updates. |

## `/api/update` request parity (fields + validation)

| Field | C++ (`/api/update`) | Rust (`/api/update`) | Parity notes |
|---|---|---|---|
| Required keys | **Partial**: validates only 7 keys (`rotationDirection,tpd,action,hour,minutes,timerEnabled,screenSleep`) but then reads many more | **Yes**: fully parsed (`UpdatePayload` → `UpdateRequest`) | Rust will reject missing `customWindDuration/customWindPauseDuration/customDuration…/rtcGmtOffset/rtcDST`, while C++ may silently treat them as empty/default-y values. |
| Type tolerance | **Low**: mostly assumes strings | **High**: strings/numbers/bools accepted for many fields | Rust has custom deserializers for “string from any” and “bool from any”. |
| Direction change | **Yes**: stops motor; sets direction; sets motor dir only for CW/CCW | **Yes**: stops motor; sets motor dir only for CW/CCW | Same behavior. |
| TPD change triggers finish re-estimate | **Yes** | **Yes** | Same formula. |
| Action START/STOP | **Yes** | **Yes** | Same semantics. |
| Screen sleep toggle | **Yes** | **Yes** | C++ has some split-brain variables; Rust cleanly updates state + display. |
| Screen schedule fields | **Yes** (optional fields applied if present) | **Yes** (optional fields applied if present) | Same shape from API perspective. |
| RTC offset/DST update triggers time sync | **Yes** (`getTime()`) | **Yes** (controller emits `SyncTime` → system task SNTP) | Both apply offset/DST and refresh clock. |
| Persistence after update | **Yes** (writes LittleFS JSON) | **Yes** (persists settings snapshot to flash JSON) | Rust persists more fields (notably `winderEnabled`). |

|---|---|---|---|

## Winding algorithm / state machine

| Feature | C++ | Rust | Parity notes |
|---|---|---|---|
| Direction modes | **Yes**: CW/CCW/BOTH | **Yes**: CW/CCW/BOTH | Same. |
| Motor direction in BOTH | **Yes**: toggles on each “cycle pause” | **Yes**: toggles on each “cycle pause” | Same intent. |
| Rotation duration setting | **Yes**: `customDurationInSecondsToCompleteOneRevolution` | **Yes**: `rotation_duration_secs` | Same. |

## Biggest parity gaps (actionable deltas)

- **WiFiManager portal parity**: Rust now has a strong captive portal + setup flow, but still lacks a full WiFiManager clone (scan list, portal timeout).
- **Motor PWM board support**: C++ has it as an optional build; Rust now has it as an optional `pwm-motor` feature (MX1508-style).
- **LED as state indicator**: Rust now lights steady-on while Wi‑Fi is disconnected and slowBlinks+reboots after provisioning, but still misses some C++ behaviors (sleep pulse indicator).

## Notable C++-only quirks that affect “parity” correctness

- **`screenSleep` split-brain**: `/api/status` reports a global `screenSleep` while most update logic sets `userDefinedSettings.screenSleep`.
- **External button logic looks broken**: `userDefinedSettings.winderEnabled == "1";` is a comparison, not an assignment.
- **`dst` load type mismatch**: stored as bool but loaded via `.as<float>()`.
- **HA RSSI sensor inconsistency**: sometimes set to “Excellent/Good/…” and later overwritten with numeric RSSI string.
